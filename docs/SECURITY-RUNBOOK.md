# Security runbook

Assign incident commander and provider contacts before production. Preserve evidence in restricted storage with UTC timestamps, release SHA, request IDs and scope; never include raw secrets, customer documents or tokens in public tickets. Treat tenant data exposure as a critical release blocker.

| Incident                 | Contain                                                                              | Investigate and recover                                                                                                                                                                                                                              |
| ------------------------ | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Credential leak          | Disable affected credential/service; restrict access; revoke sessions where relevant | Identify repositories, bundles, logs and backups containing it; rotate provider credential; deploy replacement through scoped secret store; purge exposed artifacts where possible; verify old credential fails                                      |
| Tenant isolation failure | Disable affected route/workflow and pause relevant jobs/publication                  | Reproduce with two staging tenants; inspect caller RLS, RPC checks, permissions and published projections; repair additively; rerun all isolation tests; review audit/access history and notify affected parties through approved incident procedure |
| Account takeover         | Suspend membership/profile, revoke sessions, remove unauthorized role grants         | Verify recovery identity, audit organization/platform changes, rotate compromised credentials, test stale-session denial and restore authorized grants                                                                                               |
| Malicious upload         | Revoke publication/download capability and quarantine private object                 | Verify content bytes, size/type, ownership and rendering; preserve artifact privately; recheck private bucket policies and scanner/decoder behavior before reopening                                                                                 |
| Spam/API abuse           | Pause affected forms/rules/sender and apply provider/edge limits                     | Check canonical database rate limits and Auth provider limits, idempotency/queue growth and abuse source; re-enable gradually with monitoring                                                                                                        |
| Database compromise      | Restrict network/provider access; stop workers and compromised app credentials       | Preserve audit evidence; rotate database/operator credentials; restore into isolated target; verify tenant isolation and financial/stock integrity before controlled cutover                                                                         |
| Domain compromise        | Disable domain binding/public delivery and restrict DNS account                      | Rotate registrar/DNS credentials, check records and TLS ownership, verify correct publication and removed-domain denial before reactivation                                                                                                          |

## Rotation

Supabase public keys are intended for browser use; service keys are not used by these apps. If a service key was exposed elsewhere, rotate through Supabase's supported project procedure and audit elevated access. Rotate worker login/password separately, keep its non-superuser/no-BYPASSRLS checks and verify TLS before restart. Rotate Resend and Auth SMTP credentials at their providers, redeploy/reconfigure securely and verify actual delivery plus failure handling.

For document signing keys, provision a new key ID in the private database key configuration and matching Business App secret; rehearse issuance/publication and historical document verification before retiring the old ID. Do not delete historical verification keys indiscriminately. Quotation integrity currently has its own key provisioning procedure in QUOTATIONS.md; rehearse its historical behavior before rotation. Public renderer receives no signing secret. OAuth/payment credentials are not currently configured; if introduced later, inventory and rotate at the provider. Rotate DNS/hosting credentials and backup access identities independently.

Rotate `AUTH_RECOVERY_SIGNING_KEY` independently per admin application/environment through the server secret store. Rotation invalidates pending encrypted recovery cookies; users must reopen their still-valid provider link or request another. Do not preserve a compromised key to keep pending cookies valid. Verify valid/used-token behavior and real inbox delivery after rotation; review global refresh revocation and the provider's access-JWT expiry limitation in AUTH-RECOVERY.md. Disable proxy query logging for recovery links and never capture tokens/passwords in incident evidence. DEPENDENCY-MITIGATION.md records the unsuppressed braces tooling advisory and its local guard.

## Reviewed boundaries and remaining gates

Next Server Actions provide framework same-origin protection and all privileged operations still require verified caller/permissions/RLS. Handwritten public POST routes use scoped capabilities and database validation/rate limits; audit each deployed origin and preflight response. No authenticated wildcard CORS was added. Do not extend the Server Action allowed-origins list broadly to work around a proxy configuration error.

Admin CSP uses per-request nonces, denies framing/objects and disallows production inline/eval scripts; styles retain inline allowance for existing editors. Public delivery's inline-script allowance remains a documented risk requiring deployed XSS/cache review. HTML projections originate from escaped, validated structured renderer output. PDF rendering disables JavaScript and blocks external network fetches. Media decoding/ownership and byte limits remain in existing modules. These controls do not substitute for hosted abuse, IDOR, entitlement, upload, cookie, password-reset or role-revocation acceptance.

The current high `braces` advisory is in the development lint toolchain. No patched version is listed; lint patterns are repository-controlled, but untrusted changes to build/tooling inputs remain a risk. Keep builds isolated from production credentials, retain the finding in release review and reassess upstream. Do not suppress the full audit or invent a patch. See [upstream advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).
