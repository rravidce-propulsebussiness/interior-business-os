# Phase 3 quotation contract

Design recorded before implementation. Preserve the Phase 2 calculate function and Decimal arithmetic. Customers are a shared quotation/CRM master: customer permissions plus either quotation or CRM entitlement. Projects/areas require projects entitlement and project permissions. Quotations require quotation entitlement and granular quotation permissions; catalog lines additionally require catalog and pricing entitlements. Website and Brochure are unrelated.

Customer/project masters use normalized columns and structured address objects. Projects are commercial containers, not execution/task management. Areas are industry-neutral, optionally nested, and explicitly ordered. Quotation roots identify customer/project and a concurrency-safe organization/year number; revisions hold commercial content. One draft is allowed per root. Creating a revision copies snapshots without repricing. Explicit edit/refresh recalculates just the selected line with current configuration and exposes before/after amounts.

Lifecycle: draft can be edited or cancelled; issue freezes its content and supersedes the previous issued revision. Issued/superseded content is immutable; cancellation changes lifecycle only and never destroys content. Cancelled revisions cannot be edited or reissued. No sent/viewed/accepted claim exists. Row locks and expected versions protect every draft write, issue and clone. Number counters increment atomically under organization locks; unique constraints independently protect numbers/revisions. No hard-delete API is provided for historical masters or quotations.

Browser input contains selections and intent, never trusted totals. The server reloads item-scoped configuration, runs the canonical engine and calculates quote discounts with existing Decimal arithmetic. A narrow HMAC-attested RPC commits the authoritative result. QUOTATION_SIGNING_KEY is a 32-byte hex server-only key mirrored in a private database table; no application service-role key is used. Signed messages bind actor, organization, operation, revision/version, expiry and nonce. The RPC independently authorizes every operation, rejects replays/stale versions and checks the current catalog fingerprint before saving. The key is an integrity boundary, not a replacement for RBAC or RLS. Missing configuration fails closed.

Discount order: canonical line amount, optional override, line discount, sum nonoptional lines, revision discount, final total. Fixed/percentage discounts require quotation.discount. Percentage discounts are additive to no other stage and cannot exceed 100%; fixed discounts cannot exceed their basis. Amounts remain exact decimal strings with no implicit floating-point or currency conversion. Optional lines are excluded from payable totals and reported separately. Revision discounts do not apply to optional totals. No GST/tax is fabricated.

Manual lines require quotation.override_rate and a reason. They are explicitly typed and cannot impersonate catalog snapshots. A catalog override replaces the final effective selling amount using quantity × overridden rate, retains the original canonical result, requires a reason and quotation.override_rate, and is blocked below the minimum. Discounts are likewise blocked when they would take an included line below its minimum (revision discount is checked proportionally). No approval workflow or role-name bypass exists.

Internal cost snapshots live in separate protected rows. Server-side pricing may read cost through an attested, item-scoped context; it never returns cost to an unauthorized browser. Customer documents use an explicit allowlist and never the internal calculation payload. Organization branding/terms/customer/project/area labels are detached into revision/line snapshots. Issued output never joins live catalogs or current defaults for display values.

Lists and selectors use bounded server-side search/page queries. Item configuration loads only the selected item's questions/options/rates/modifiers and eligible books. UI uses explicit Save, displays pricing changes, and retains the existing shared components, authorization service and database adapter.

## Setup and operating limits

Generate 32 random bytes with a cryptographic generator and store their lowercase hex encoding in `QUOTATION_SIGNING_KEY` in the Business App's server environment. Never use a `NEXT_PUBLIC_` variable. Configure the same value in the private database with `node packages/database/scripts/configure-quotation-key.mjs`, supplying the operator database connection as `TEST_DATABASE_URL`. The script passes SQL on standard input and never prints the key. Rotation invalidates outstanding calculation proofs; update the database and application together. Missing configuration disables quotation writes while customer/project masters remain usable.

Apply `seed-commercial.sql` after confirmed development accounts and the Interior catalog seed. It creates Ravi Residence, the 3BHK demo project, three areas and independent quotation branding defaults. It does not create fake Auth users or overwrite edited records.

Drafts support duplication and arrangement without repricing. The separate **Recalculate and save line** action explicitly reloads current configuration. The preview is advisory; the server always computes the saved price. Each revision is limited to 200 lines so the document read remains below the default PostgREST row cap. Area selectors show up to 250 project areas; contacts show up to 100 records. Larger-scale area/contact navigation is deferred. Organization-scoped staff permissions are supported; branch-only role assignments fail closed for these organization-level workflows. Project branch references and branch-specific price resolution remain supported.

Estimated Contribution means saved selling amount minus saved estimated cost, excluding optional items. It is not realized profit. If any included line lacks an estimated cost, the summary is explicitly unavailable instead of treating missing costs as zero. Manual cost entry is currently API/domain capability; the UI creates manual lines without an estimate. Branding accepts a bounded PNG/JPEG upload embedded into the immutable document snapshot. No public Storage bucket is required.
