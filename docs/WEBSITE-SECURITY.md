# Website security and deployment

All new tenant tables force RLS. Authenticated direct writes are revoked; checked security-definer RPCs use an empty search_path, organization locks, tenant identity, granular permission, website assignment and entitlement checks. Raw document/snapshot columns are not directly selectable. Checked reads redact developer source without its view permission. Public RPCs expose only the current published projection, referenced asset bytes and a generic enquiry confirmation.

Configure WEBSITE_BUILD_KEY_ID (default primary) and WEBSITE_BUILD_SIGNING_KEY only on the Business App server. Use at least 32 random bytes encoded as a string. Provision the identical UTF-8 string in private.website_build_keys.secret with key_id and active=true using a trusted database administration connection. It is not a service-role browser key. Do not put it in NEXT_PUBLIC variables, shell history, logs or a committed SQL file. Signed payloads expire after five minutes; the database rejects expired/forged or incorrectly scoped purposes. Rotate keys by adding a new active ID, changing the server environment and retiring the old ID after in-flight requests expire. The public renderer needs only the existing publishable database key.

Uploads use authenticated, same-origin, bounded requests. Image bytes are decoded with a 40-million-pixel ceiling and converted to metadata-stripped WebP within 1920 pixels. PDF/MP4 containers receive signature checks; PDFs are downloads, never trusted inline HTML. Files are capped at 10 MB and checked against per-organization storage limits. The concrete local storage adapter uses private database bytea records, not an exposed bucket; plan capacity should remain modest. An external object-store adapter and malware scanning are deployment enhancements, not claimed as verified here. Referenced historical media cannot be destroyed.

The public app sends CSP, nosniff, no framing and a restrictive Permissions-Policy. Tenant custom code executes only inside opaque sandbox frames. Separate public website and Business App origins and host-only authentication cookies are required deployment boundaries. The generated runtime uses inline styles and trusted bootstrap/JSON-LD, so the outer CSP permits inline script; custom HTML/JS must never be interpolated into that outer document.

Public forms bound request bodies, validate configured fields and explicit consent, rate-limit by site/minute in the database, ignore honeypots and reuse canonical CRM duplicates. No secret service-role key is used. Metrics are daily aggregate counts, not personal tracking. Production edge abuse controls can supplement the application quota.
