## Final local results

- Fresh database verification applied 101 migrations (89 preserved and 12 additive) and passed 1,071 SQL assertions. Hash checks confirmed all 89 earlier migrations unchanged.
- Latest database-enabled Vitest run: 227 tests across 33 files passed, including canonical follow-up/activity idempotency and source/cost permission revocation.
- Playwright: 33 passed, 78 skipped, zero failed across the 111-case application matrix. Skips include cases for other application targets and credential-dependent hosted acceptance.
- All three production builds, lint, full workspace and tooling TypeScript, formatting, generated database types, seed checks and frozen-lockfile install passed. Email adapter: ten tests passed without sending mail.
- Secret-pattern scan: 68 browser JavaScript files and 78 worker/email/report/shared source files passed.
- Larger canonical-source workload: 1,000 invoices in 1,450 ms; 1,000 projects in 916 ms; 1,000 tasks in 3,295 ms; 2,000 inventory movements in 153 ms; a page over 10,000 audit rows in 3,966 ms. Fixtures roll back and preserve stock guards.

## Reproduction

Create a new disposable PostgreSQL database, set `TEST_DATABASE_URL` and `ALLOW_TEST_DATABASE_RESET=yes`, then run `pnpm db:verify`. The verifier refuses nonempty databases. Run `pnpm test`, `pnpm db:types:check`, `pnpm db:seed:check`, `node --test scripts/automation-email.test.mjs`, `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm security:client`, `pnpm format:check` and `pnpm test:e2e --workers=2`. Use `E2E_PORT_OFFSET=10` when ports 3000-3002 are occupied.

Race fixtures deliberately commit history and require a separate disposable clone plus `ALLOW_AUTOMATION_RACE_FIXTURES=yes`. Run `node packages/database/scripts/test-automation-concurrency.mjs`, then `node packages/database/scripts/test-automation-performance.mjs`. The latter rolls back its 10,000-row fixture. Never run separate Playwright suites simultaneously because they share output cleanup.

Local evidence logs are under `.tools/phase10-*.log`; report PDF fixtures and render sheets are under `output/pdf/phase10`. SQL finance/procurement/execution fixtures verify canonical events and report reconciliation separately from the PDF layout fixtures. Component fixtures do not claim hosted authentication or server-action acceptance.

## Remaining scope and acceptance boundaries

Local verification does not establish production readiness. Hosted owner/denied-role/domain automation flows, deployed RLS/PostgREST behavior, multi-worker deployment and real provider delivery remain unexecuted. The opt-in hosted smoke scenario covers a paused rule and authorized report export; it is not exhaustive end-to-end coverage of every domain.

The large-history timing fixture concentrates 10,000 notifications/executions on a repeated source, plus 10,000 distinct CRM records. It is not a worst-case distinct-source authorization benchmark. Those initial timings preceded additional dimension queries. The larger invoice, task, project, inventory and audit measurements above include the latest queries; sustained multi-tenant capacity still requires dedicated load testing. These synthetic local measurements are not production latency guarantees.

The UI includes a global notification bell/dropdown, customer consent editor, escalated work view, combined customer activity timeline and CRM pipeline visualization. Project/customer pickers support text search with a 100-match cap. Detailed subcontractor money stays in the project-cost service; the standalone subcontractor report is status/quantity-oriented. Other report dimension summaries use tables rather than a full chart suite. Picker results do not provide paging beyond the match cap; narrow the search.

CSV is Excel-compatible; native XLSX is not generated. Report data snapshots are immutable, but generated PDF bytes are not stored as immutable binaries and can vary with Chromium metadata. Existing renderer version 1 must be retained if later layouts change. No historical receivables reconstruction, accounting profit, subjective health score or fabricated resolution average is introduced.
