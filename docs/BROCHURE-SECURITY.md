# Brochure security and deployment

Brochure is independently entitled through the existing module system. Plan defaults and organization overrides govern brochure count, pages, storage bytes, templates, custom design, public sharing and aggregate analytics. Server actions and database RPCs both check authorization. UI visibility never grants access.

Permissions: `brochure.view`, `brochure.manage`, `brochure.publish`, `brochure.restore`, `brochure.export`, `brochure.media.manage`, `brochure.forms.manage`, `brochure.brand.manage`, `brochure.share`, `brochure.analytics.view`. Existing owner/admin roles receive grants. Brochure Designer is separate from Website Developer and receives no customer, quotation, contract, finance or Website permissions. Assigning it requires existing role-management authority and possession of the delegated permissions.

Tenant tables force RLS. Direct document/snapshot/kit writes and raw payload reads are revoked. Checked security-definer functions use an empty search path and explicit organization/permission checks. Composite foreign keys preserve tenant ownership. Versions, PDFs and events are immutable even against accidental privileged updates. Private byte storage, rate counters and metrics have no public grants. Public projections resolve only currently published, shared and entitled snapshots.

Use `BROCHURE_BUILD_KEY_ID` and `BROCHURE_BUILD_SIGNING_KEY` on the Business App server, or reuse the existing Website signing configuration. Provision the identical UTF-8 secret (at least 32 bytes) into the existing private `website_build_keys` table using a trusted administration connection. The shared key infrastructure does not require a Website entitlement. Keep keys out of NEXT_PUBLIC variables, logs, browser bundles and checked-in SQL. Five-minute proofs bind purpose, organization, draft revision, exact document digest and generated PDF digest. Key rotation follows WEBSITE-SECURITY.md. Public delivery uses the existing publishable database key, never a service-role key.

Uploads are authenticated, same-origin, bounded, decoded under a 40-million-pixel ceiling and converted to metadata-stripped WebP. Print originals preserve decoded dimensions; editor/public thumbnails are generated separately. The existing media metadata and private byte store are reused. Historical references prevent archiving. Draft preview can resolve approved kit assets only through bindings in that draft; adding a logo to the current kit never widens an old snapshot's access.

Structured schema validation rejects unknown/executable properties and unsafe links. All rendered content is escaped. PDF rendering disables JavaScript and network access. Public enquiries use explicit consent, field allowlists, length bounds, honeypots, transactional quotas and normalized CRM duplicate checks. Daily aggregate counts may be inflated by automated visitors; they are not unique-person analytics.

Deploy the Business App and public Websites app on separate origins with host-only authentication cookies. Apply all additive migrations, configure public origin and signing keys, install Chromium and run opt-in hosted Auth/PostgREST acceptance before production use. Local PostgreSQL results are not a substitute for hosted acceptance.
