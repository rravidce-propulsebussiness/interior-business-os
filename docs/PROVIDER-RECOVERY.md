## Worker interruption

Phase 11C adapter clarification: the current website/brochure media implementation stores private `bytea` in PostgreSQL. Its bytes belong in database backup/restore verification and must be checked by asset count/checksum and authorized/public capability behavior. The external bucket/object-backup procedure above is conditional and currently **NOT APPLICABLE** because no external adapter is configured; it is not a substitute for the still-BLOCKED hosted database-media recovery gate. Do not create a bucket or make private media public to satisfy acceptance.

Precondition: disposable database/queue, restricted worker login, outbound email disabled or staging sink, lease/idempotency snapshots. Pause the supervisor, terminate only the identified staging worker process after a claim, retain the database, wait for the actual configured lease expiry and restart one worker through `node scripts/start-service.mjs worker`. Expected: expired claims retry through existing lease recovery, committed actions remain unique and pending jobs are not silently discarded. Repeat restart; compare pending/running/dead-letter counts, unique notification/task/delivery keys and ledger/audit history. Rollback: pause worker, preserve leases/history and restore prior compatible worker/configuration; never delete outbox rows or force sent state. Local concurrency and restart evidence is recorded in PHASE11-VERIFICATION.md; hosted supervision/crash/email-acknowledgement recovery remains BLOCKED.

## Local database restoration

Use PostgreSQL `pg_dump -Fc` against the explicitly named disposable verification database, create a different empty disposable database and `pg_restore --exit-on-error` into it. Run database regressions, generated-type checks and readiness assertions against the restore. Preserve the original and archive privately. This verifies PostgreSQL schema/data round-trip only; it excludes provider-managed Auth configuration, Storage bytes, hosted backup entitlement and deployed cutover. Never run `db:verify` on a restored or nonempty database. Record actual elapsed time; hosted RTO/RPO remain unmeasured and unapproved.
