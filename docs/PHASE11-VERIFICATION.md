No production source maps, credentials, RLS exemptions or failing tests were introduced to obtain a pass.

### Failures fixed and retained as evidence

Initial unit runs timed out in nested full-schema/full-regression setup, and repeated use of a database with committed race fixtures exposed a multi-page report snapshot bug: `rows || batch -> 'rows'` parsed in the wrong order. The additive migration preserves existing permission checks, 5,000-row bound, renderer metadata and audit behavior; it only parenthesizes the appended row array. The regression validates complete counts, first-page ordering and absence of duplicate/missing IDs, including reports with more than 25 rows.

The concurrency test now invokes the same fresh initializer with `--initialize-only`, including the demo-organization dependency; all its race assertions and timeouts remain unchanged. Default `db:verify` still runs the full assertion suite, and initialization explicitly claims no full regression PASS. Final tests use a clean database, not deleted ledger/history records. Initial failures and final results remain under .tools/phase11b-*.log.

The recovery harness initially used an incorrect working directory, constructed a malformed fixture link and rejected the SDK's null protocol challenge fields. These fixture defects were corrected without an application auth bypass. Browser checks also found and fixed loss of error state when the server cleared the pending cookie. Its revocation-failure test now requires both the specific password-changed/revocation-incomplete message and a recorded password update without successful logout. Tokens/passwords are excluded from traces/screenshots/video for recovery tests.

The first default browser run was 37 passed, 79 skipped, one failed: a Next shell still hydrating after `setContent` inserted a second robots tag into the standalone preview fixture. That test now navigates to an isolated HTML response carrying the actual application's CSP; metadata, preview selection and disabled submission assertions remain intact. Its three-case renderer regression and final full default suite pass. Initial JSON, trace and log are retained privately; final JSON has 38 expected, 79 skipped, zero unexpected/flaky.

The expanded source scan flagged a deliberately synthetic password-bearing loopback URL in an existing environment test. The fixture now constructs that URL through the URL API, with the same rejection assertion. No real credential, audit finding or scanner rule was excluded. A generated recovery-secret canary was rejected by both scanners without logging its value, then removed.
