# braces advisory disposition

Status: MITIGATED locally, upstream advisory still OPEN. The full unsuppressed audit reports [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) against braces 3.0.3 through development-only eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch. The production dependency audit is evaluated separately. Do not describe a clean production audit as a clean full audit. No fixed braces release was published when checked; upgrading to another affected version would not resolve the issue.

Phase 11D recheck on 2026-10-05: the official GitHub advisory still lists affected versions through 3.0.3 and no patched version. Runtime exposure remains the development lint chain; production audit is recorded independently. Upgrade only when a reviewed fixed upstream release is available, remove the local patch only after the actual regression/audit/lint/build checks, and create a new RC for that dependency change. Release-owner acceptance of residual risk is currently BLOCKED, not an automatically accepted risk or RESOLVED finding.

`patches/braces@3.0.3.patch`, registered in pnpm-workspace.yaml and the lockfile, adds an iterative AST validation before recursive compile/expand. It bounds nested nodes at 128 levels and inspected nodes at 131,072, throwing `ERR_BRACES_AST_LIMIT` instead of overflowing the call stack. Parent references are not followed. The guard also applies to a preparsed AST. It preserves normal glob expansion and rejects excessive patterns deliberately; unusual repository globs beyond the bounds must be simplified, not exempted.

Run frozen install, `pnpm security:dependency`, lint and the full/production audits. The three dependency tests resolve the actual lint chain rather than an unrelated root package: an under-parser-limit nested attack, preparsed-AST bypass and ordinary braces/micromatch/repository glob behavior. CI runs the regression check; pnpm verifies the recorded patch checksum during install. Audit output is retained privately under `.tools/phase11b-audit-*.json`. No audit ignore or severity downgrade is used.

Residual risk: the patch is a local mitigation, not an upstream security release or a general bound on expansion output. Other pathological patterns and future changes require review. Keep lint/build tooling isolated from production credentials and execute only trusted repository inputs. Repository maintainers own this mitigation; deployment owners must review it before release. Remove it only after a reviewed upstream fix, updated frozen lockfile, advisory reproduction checks, full lint/build/test results and a newly reviewed audit. Current production decision remains NO-GO for critical hosted/provider blockers, independent of this mitigation.
