# Phase 4 implementation and verification

Phase 4 surrounds the existing quotation engine with CRM and customer responses. Phase 0-3 migrations and pricing/snapshot architecture are preserved. No Phase 5 billing, payment, procurement or execution feature is added.

1. **Workflow:** enquiry, qualification, activities, follow-ups, site visits, requirements, conversion, existing quotation creation/issue, secure sharing and immutable customer response.
2. **Tables:** lead_sources, crm_pipeline_stages, crm_lost_reasons, crm_requirement_fields, leads, lead_activities, lead_followups, site_visits, quotation_share_links and quotation_customer_responses. Private counters, token hashes and rate-limit buckets support them.
3. **Migrations:** six additive migrations 20261001000000_crm_schema.sql through 20261001000500_crm_inactive_source_edits.sql. Earlier migrations are unchanged.
4. **Leads:** organization reference/number, contact/company, original and normalized phone/email, source, industry, branch, assignee, priority, budget, site, dates, notes, requirements and conversion attribution. Number counters serialize per organization/year and are prefix-ready.
5. **Pipeline:** configurable tenant stages with stable open/won/lost semantics, ordering, active state and generated terminal flag. Display names do not drive lifecycle logic.
6. **Activities:** append-only manual communications and distinct system events, linked to the original lead and paginated by time.
7. **Follow-ups:** assigned pending/completed/cancelled tasks with due time, note, completion actor/outcome and idempotent completion. Pending tasks derive the lead's next follow-up.
8. **Visits:** scheduled/completed/cancelled/rescheduled visits retain lead linkage and gain project linkage on conversion. Notes capture preliminary observations; no BOQ is introduced.
9. **Conversion:** organization/lead locks, permission/entitlement checks, tenant-bound Customer/Project selection or creation, atomic rollback and repeatable mapping. Existing customer data is preserved.
10. **Duplicates:** tenant-local normalized phone/email warnings, bounded match lists, explicit acknowledgement before creating a matching customer; no automatic merge.
11. **Share design:** 32 random bytes encoded as 64 hex characters, tied to one issued revision, optional link expiry/PDF, revocation and atomic rotation.
12. **Token security:** only SHA-256 hashes in a private table. Raw token appears once on creation. It is excluded from business lists/audit payloads; deployment logs must redact bearer paths/parameters.
13. **Public projection:** explicit allowlist of frozen branding, customer/project/site, item specifications, quantities/display rates, optional items, totals and terms. No cost, minimum, modifier, staff, CRM or internal-ID payloads.
14. **Responses:** append-only approved/changes_requested/declined records contain customer name/comment/acknowledgement, exact share/revision, server amount, currency, timestamp and snapshot hash. Same-response retry is idempotent; conflicting response fails.
15. **Expiry/revisions:** invalid link fails; commercially expired quotations remain viewable but cannot receive responses. Rev 1 remains exact and historically viewable after Rev 2 issue, with a superseded label and disabled response controls. New issuance never redirects old amounts.
16. **Commercial state:** approval produces a commercially accepted quotation/project read model. Manual Won requires permission/reason; issue alone never wins a lead. Decline never silently loses the lead. Optional selections remain read-only and excluded from acceptance.
17. **Permissions:** lead.view/create/manage/assign/convert/win; crm.activity.create, crm.followup.manage, crm.site_visit.manage, crm.pipeline.manage, crm.source.manage; quotation.share and quotation.customer_response.view.
18. **Security:** ten forced-RLS tables, tenant composite foreign keys, SELECT-only application access, fixed-search-path checked RPCs and narrowly granted anonymous public RPC. CRM/Quotation/Projects entitlements remain separate from Website.
19. **Audit:** significant lead/task/visit/conversion/share actions, first view and customer responses reuse transactional audit infrastructure; customer refreshes aggregate view counters.
20. **Business routes:** /dashboard/crm, /leads, /leads/new, /leads/[id], /leads/[id]/convert, /pipeline, /followups, /site-visits, /settings and /commercial. Existing Customer/Project/Quotation pages link originating history and customer response state.
21. **Public routes:** Business App /q/[token], /pdf and /respond, with private/no-store, no-referrer, CSP, explicit acknowledgement and same-origin POST checks. PDF reuses the existing customer renderer.
22. **Unit/integration results:** 109 tests across 15 files passed with the database configured; the original Phase 0-3 suites remain included. The expanded sharing test also passed after adding public-PDF, revision-forgery and decline assertions.
23. **Database assertions:** Fresh phase4_acceptance migration/seed verification passed (228 initial assertions). The expanded final db:test run passed 245 assertions. Generated types and both seed drift checks passed. CRM assertions are now part of db:verify/db:test.
24. **Playwright:** final `pnpm test:e2e --workers=1` run passed: 16 passed, 29 skipped, exit code 0. Anonymous CRM/public-route checks, authentication boundaries, responsive shells and multipage quotation PDF rendering passed. Skips cover inapplicable app projects and opt-in hosted scenarios; hosted sales/conversion/change-request/approval acceptance remains outstanding.
25. **Builds:** Business App, Platform Admin and Websites production builds passed. Frozen installation, strict typecheck, formatting and the client-bundle scan passed; the scan examined 50 JavaScript bundles and found no privileged environment names or server-secret canary.
26. **Hosted acceptance:** outstanding. No configured development Supabase URL/key, confirmed live accounts or matching hosted signing setup was available. Local Auth-shim tests are not described as hosted acceptance.
27. **Limits:** organization-wide grants required; branch-only CRM grants fail closed. Selector pages contain 25 rows. No attachments until private Storage acceptance; no external notifications; optional items require a revision to include them. One decisive response per revision. Ingress rate limits and token-log redaction are deployment requirements. Valid-link limits use PostgreSQL, not process memory.
28. **Phase 5 recommendation:** first complete hosted acceptance, then separately scope invoice/tax/commercial handoff requirements, financial rounding and idempotency against accepted revision references. No automatic invoice or execution work is started.
