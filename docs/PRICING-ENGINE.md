# Pricing contract (Phase 2)

These decisions precede implementation. One pure engine in quotation-engine prices finished work, never raw material consumption. Input decimals are strings (up to six fractional digits); exact BigInt rational arithmetic avoids binary money arithmetic. No eval, database JavaScript, clock reads or randomness occurs in calculations.

Resolution at an explicit ISO calculation instant: a selected active, in-window, currency-compatible price book; otherwise branch default; otherwise organization default; otherwise item default rate. An invalid explicit book is an error. Within the chosen book, an effective item rate overrides the effective item default. Missing book rates fall back to the item default. Windows are half-open [from, until); inactive rates are ignored. Ambiguity is an error, never a newest-row heuristic. Branch books require a matching active branch. Currency is explicit; no exchange conversion exists.

Measurement uses allowlisted methods: manual, width_height, length, area, volume, count, lump_sum and percentage. Percentage quantity is a positive percentage input divided by 100, applied to the configured base rate. Custom units use manual quantities; arbitrary custom formulas are reserved. Dimensional units must match the method and inputs use the displayed unit system, with no implicit conversion.

Calculation order: resolve rate; measure and round quantity; add selected per-unit modifiers; multiply quantity by adjusted rate; add fixed modifiers; apply the sum of percentage modifiers to that same subtotal; round final amount. Thus 10% plus 5% means 15%, not compounding. Modifiers are sorted by stage, sort_order and stable ID for reproducible breakdowns. Negative modifiers are allowed within bounds, but negative resulting rate/subtotal/total is rejected. No tax, discounts or overrides are applied.

Rounding supports none, nearest (ties away from zero), up and down with a positive decimal increment. Quantity and amount have separate rules. No-rounding returns the exact decimal result; future payment/quotation workflows must choose currency settlement rounding explicitly. Minimum rates return a threshold and below-minimum signal; they never silently clamp the calculation. Estimated internal cost is separately permission-gated and never part of customer projections.

Dependencies are AND conditions using equals, not_equals, in or not_in against same-item select/multi-select option keys. Graphs must be acyclic. An unanswered or hidden parent makes its condition false, including negative operators. Hidden/stale answers are removed before pricing and snapshots. Required visible questions must be answered; inactive/foreign/unknown options are rejected. Defaults apply only to visible active questions. Hidden-to-sales questions cannot silently contribute price.

Results contain copied labels, specifications, measurement inputs, selected price-book/rate identifiers, rates, modifier values, rounding deltas, totals, minimum metadata and calculation version. Results are JSON-compatible values with decimal strings, never references to mutable masters. Future quotation lines persist this complete snapshot; they must not recalculate an old quote from current masters.

The minimum warning compares the final rounded amount with rounded quantity multiplied by the configured minimum rate, so fixed and percentage adjustments participate in the effective selling amount. Estimated cost is quantity multiplied by the independently stored estimated cost rate; it is an exact estimate, not a currency-settlement amount. No foreign exchange, tax or implicit currency rounding is performed. Input precision is at most six fractional digits and twelve integral digits; multiplication preserves exact results beyond input precision. Final amount rounding is configured explicitly (the editor initially offers nearest 0.01, which administrators must adjust for their currency/workflow).

Rates use immutable values and effective windows. Replacing an open rate closes it and inserts a new row atomically, checking the expected version. Other configuration is soft-disabled and audited; existing serialized snapshots preserve its old labels/modifiers. Historical calculations with current configuration are not a substitute for saved quotation snapshots.

Example: 8 × 7 = 56 sq ft; 1550 + 180 + 100 + 500 + 150 + 70 = 2550 per sq ft; total 142800. The shorter BWP + PU + Hettich example is 2380 × 56 = 133280. Names and prices are demonstration data only.
