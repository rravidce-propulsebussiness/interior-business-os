## One hosted command

```powershell
pnpm acceptance:hosted --env-file=.env.acceptance.local
```

Execution order: presence/type validation → reviewed target/scenario parsing → independent remote staging marker → read-only migration/catalog verification → three actual HTTPS health/readiness/header probes → registered A/B fixture validation → real identity login/refresh/logout and platform separation → foreign-row/RPC and staff platform-write denial → configured canonical/provider scenarios → opted-in existing live browser tests → optional real SMTP/inbox recovery → session cleanup → required-case coverage report.

If critical prerequisites are missing, the runner exits **2 before any network request or fixture creation**. Exceptions/provider bodies are never printed. Exit 1 means observed FAIL/internal tooling failure; exit 2 means required checks remain BLOCKED; exit 0 means the selected mode completed without failures/blockers, **not production certification**. `acceptance:preflight` can exit 0 for valid configuration without executing any hosted test; its report leaves those cases BLOCKED. JSON and Markdown results are written under `.tools/acceptance/<run-uuid>/`. Each check records test ID, verified/unverified environment, UTC timestamp, result, category, evidence reference and failure reason. Numeric/UUID evidence is allowlisted; bodies, emails, credentials, cookies and capability URLs are excluded.

## Request/assertion plans

Copy `scripts/acceptance/scenarios.example.json` into an ignored private plan. The example has real canonical RPC request shapes; it is **not** comprehensive acceptance. `scripts/acceptance/coverage.mjs` lists every independently required behavior, which remains BLOCKED unless that exact test executes. Missing business/provider scenarios are explicit remaining work; supplying a credential does not magically implement a missing test.

Supported steps are RPC, REST, HTTPS application/provider requests and bounded waits. Requests require an expected HTTP status **and nonempty assertions**. JSON pointers support equality, nonempty/empty arrays, membership and numeric minimum. PDF assertions validate MIME/signature and parse a nonempty document. Capture only non-secret business IDs/data in memory and reference `${capturedId}`, `${orgA}`, `${orgB}` or environment-supplied `ACCEPTANCE_*` inputs. Denials require an explicit provider authorization code; a timeout/500/empty fixture cannot pass denial. Provider steps use reviewed HTTPS origins and protected bearer tokens; no arbitrary shell command, SQL repair, local mock or external redirect is accepted. Plan input is trusted operator test code and must be reviewed for tenant scope and meaningful expected values before execution.

Mail receipt, expected totals, historical snapshots and ledger/worker idempotency need independently known expected values and real provider/database evidence. An API being reachable does not certify that business flow. Current application request steps are anonymous HTTP unless the actual endpoint supports supplied capabilities; authenticated UI/Server Action cases belong in the hosted Playwright suite. Provider control APIs differ: supply exact real paths/response assertions for the selected supervisor/hosting/monitoring/backup provider; do not invent a generic endpoint and declare it implemented.

## CI

The performance runner validates the whole plan before making requests, signs into the actual Business App Owner A session for business routes, switches to the registered A organization and rejects redirects/non-200 business responses. Dashboard-family targets must be dashboard routes. Requests are sequential with 100 ms spacing and a 120-second sampling budget per target; this is a harness safety bound, not an invented production SLA. The single hosted command also runs a nonempty configured performance plan. Browser response timings measure full HTTP responses, not a claimed user-perceived paint metric; worker execution latency still needs actual hosted execution timestamps and its own scenario.

The optional expired-recovery drill uses a protected `ACCEPTANCE_SUPABASE_CONTROL_TOKEN` to read the intended project's actual [Auth configuration](https://supabase.com/docs/reference/api/v1-get-auth-service-config), requests a fresh real recovery email, waits for its configured OTP expiry and verifies denial plus unchanged working password. It supports provider TTLs up to five minutes; longer configured TTLs or missing control access return BLOCKED. It never changes the provider's expiry setting, advances a clock, forges a token or treats token reuse as expiry evidence.

Configure required reviewers and staging-only secrets in GitHub. Normal PR CI runs harness safety tests without hosted credentials. Hosted CI does not deploy, initialize markers, provision accounts or repair schema.
